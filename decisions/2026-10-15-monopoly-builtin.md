## 形态裁定（v1）：双人环线经营 + 全明信息

- **角色**：`['red','blue']`——人类缺省执 red、Agent 缺省执 blue（sessions.start
  的 humanRole 缺省 roles[0]、game_start 的 role 缺省取另一方）。双人对局是 v1
  会话的硬裁剪（`sessions.start` 拒 `players.max !== 2`，见 sessions.ts），本款
  照此裁成**双人环线经营**；多人（3-4 人）与「AI 对手由引擎代打」均不实现（后者
  与既有一切内置同纪律：AI 对手 = LLM Agent 经 `game_move` 真实来打）。
- **棋盘**：24 格环线（7×7 外圈，视图与引擎同构）：起点 1、地产 14（地价
  100-750）、机会 4、税局 2、派出所 1、免费停车 1、年度分红 1。
- **对局主干**：1d6 掷骰前进（经过或停留起点领 200 薪水）→ 落地结算（买地/
  加盖/付租/缴税/抽卡/拘留）→ 回合收尾；资金 1500 起步。
- **终局两途**：破产（任何应付不足——剩余现金归对手、对手胜）与每人 16 回合
  上限的净值裁决（现金 + 地价 + 已付加盖费，相同为平局）。
- **信息面（本款的特点，如实标注）**：大富翁棋盘类信息天然全明——桥契约里
  「state 对视图/Agent 全量下发、无按角色脱敏通道」在本款不构成公平性问题
  （对照 21 点「暗牌延迟决定」与军棋「暗棋不实现——接口事实裁定」两条既有路线，
  本款无需在「延迟决定 / 诚实明棋」之间取舍；机会牌序虽在 `state.deck` 中可读，
  但序对双方同等可读且不构成行动优势）。

## 规则面裁剪（v1 明示）

| 面 | 判定 |
|---|---|
| 掷骰移动 + 经过/停留起点薪水 | ✅ 全量实现 |
| 买地（停留无人地产）/ 加盖（停留自有地产，最高 3 级、每级=地价一半） | ✅ 实现（一次停留一次决定，随后回合结束） |
| 收租（地价 × 30%/70%/140% 按等级） | ✅ 实现 |
| 机会卡 12 张（现金 ±/前进/后退/前往起点/进派出所/向对手支付） | ✅ 实现（牌堆循环、移动卡落地照常结算） |
| 税局（-150/-200）、年度分红（+200）、免费停车（no-op） | ✅ 实现 |
| 派出所（停留或卡片送入 → 下一回合掷骰空转一次） | ✅ 实现；**保释金/出狱途径不实现** |
| 破产（任何应付不足）与净值终局（16 回合上限） | ✅ 实现 |
| 抵押 / 变卖 / 协商交易 | ❌ 不实现（无债务协商面——破产是唯一止损；低现金玩家遭遇高租金会猝死，边界如实留档） |
| 多骰与连击（双骰、掷出对子再掷） | ❌ 不实现（1d6 单骰，回合模型保持「一掷一决定」） |
| 酒店/旅馆等额外升级层级 | ❌ 不实现（3 级封顶） |
| 多人对局（3-4 人） | ❌ 不实现（v1 会话硬裁剪 players.max===2） |

**两条可达性裁定（实现期自纠，如实留档）**：①「机会→机会」防连锁规则初版
**不可达**——卡组步数 {+3,-2,+2} 下没有任何机会格能落到另一机会格；把一张卡
改为「前进 4 格」后 14→18 的连锁可达（二次机会不抽卡，spec 钉死该路径）。
②「机会移动不发薪水」初版同样**不可达**（移动卡最远只到 22，无一跨过起点）；
把「后退 2 格」改为「后退 3 格」后 2→23 的后退跨起点可达（spec 钉死现金不增）。
两处都是「规则写在文档但代码路径不可测」的死规则，主动收敛为可达 + 可测。

## 平衡面（300 局 × 3 策略盲测，如实留档）

以真实引擎（esbuild 打包后 node 直跑）对 300 种子 × 3 策略做整局盲测：
激进（买得起就买、能盖就盖）/ 稳健（留 300 才买、留 500 才盖）/ 随机（50% 买、
30% 盖）。三版参数对比：

| 参数版 | 破产率（激进/稳健/随机） | 平均掷骰 | 先后手（红胜率） |
|---|---|---|---|
| 起步 2000、等级系数 20/50/100%、上限 20 回合 | 47% / 27% / 9% | 33-37 | 50/54/50% |
| 起步 2000、系数 25/60/120%、上限 16 | 30% / 19% / 5% | 28-30 | 55/57/53% |
| **起步 1500、系数 30/70/140%、上限 16（最终）** | **44% / 30% / 14%** | 26-29 | 51/52/51% |

最终版被选中的理由：被动打法不再打满 40 掷（上一版「随机」策略平均 37 掷、
大部分对局拖到上限裁决）；破产中位在双方合计 23 回合（约 17 次掷骰 + 决定），
**对局节奏与聊天场景的往返成本匹配**；先后手差在 ±1σ 内。盲测为一次性验收
产物（脚本在会话 scratchpad，不入库；统计口径：整局终局原因、掷骰数、回合数、
终局资金和、破产局回合数中位）。

## 确定性设计（seed 派生双流）

- **骰子流**：第 n 掷（0 基）= `1 + floor(mulberry32(streamSeed(seed, n+1))() × 6)`；
- **机会牌洗序**：`Fisher-Yates(mulberry32(streamSeed(seed, 0)))` → `state.deck`
  （卡 id 的排列），`deckIndex` 越尾取模循环重抽；
- `createGame(options)` 读 `options.seed`（number 则用之），缺省 `node:crypto
  randomInt`——**全文除该处外禁 `Math.random`/`Date.now`**，spec 扫源码钉死；
- **探针取证（spec 钉死，不镜像 PRNG）**：seed 7 前六掷观测值 = 1,4,4,5,1,5
  （受控用例据此把红方从指定格掷到目标格）；seed 1 的牌序 =
  `[4,7,2,0,11,5,1,9,10,3,8,6]`（视图静态预览局面逐字段对账）；
- 重启续局 = 重读会话文件用 `{seed, rolls, deck, deckIndex}` 重建，骰子与牌序
  全程可重放（spec 有整局事件流两次一致的用例）。

## 落法（四层）

1. **引擎**（`builtin/monopoly.ts`）：`GameEngine` 四面——
   `createGame`（红先、资金 1500、地产全空地、洗牌）；
   `legalActions`（终局 []；掷骰阶段恒 `[{roll}]`；决定窗 `[{buy|build},{pass}]`）；
   `applyAction`（校验序：形状 → type 已知 → 未终局 → 角色 → `actor===turn` →
   阶段闸（roll 只在掷骰阶段、buy/build/pass 只在决定窗且 pending 匹配）→ 决定窗
   防御性复查 → 应用；深拷贝、中文报错）；`describe`（掷骰/购买/加盖/放弃/跳过/
   未识别回落）。landing 结算单一收口 `settleLanding(next, role, events,
   allowChance)`（掷骰与机会移动共用；`allowChance=false` 即防连锁闸），
   支付统一走 `payOrBust`（不足即破产：剩余现金归对手、终局）。
2. **视图**（同文件内联 `viewHtml`，ASCII 标记 `data-game="dsh-tavern.monopoly"`）：
   7×7 外圈棋盘（24 格按 `ringPos` 计算 grid 行列）+ 中央面板（双方资金/地产数/
   位置/回合数/滞留标记 + 最近骰点 + 最近一手叙述）；四按钮（掷骰/购买/加盖/跳过）
   **随 `view.legal` 收缩**（决定窗里掷骰禁用、掷骰阶段里三个决定按钮禁用）；
   归属格渲染 owner 描边/等级星/租金副文案/双色棋子点；终局为**盘面之下的
   in-flow 结果条**（沿 21 点 2026-10-14 截图驱动修订的既定语义：盘面完整保留、
   零叠压），结果条按 `session.players` 的 owner 反查落「你/AI」章；无 token 渲染
   静态预览局面（= 引擎 `createGame({seed:1})` 开局态，spec 逐字段对账防漂移）。
3. **registry / gates**：装载数组加第六项（零其他改动）；`server-bundle` gate 增
   `dsh-tavern.monopoly` 标记 + `monopoly-removed` 负样本自测（子串救活防护同款；
   gate 数保持 15）。
4. **版本连带（0.6.4 → 0.6.5，特性增量）**：`packages/plugin/package.json` 与根
   `package.json` 升补丁位；`examples/mods/dsh-tavern.story-clock/mod.json` 的
   `engines` `^0.6.4`→`^0.6.5`（`tavern-mods-examples.spec` 用真实版本逐字守卫，
   漂移即红）；`docs/mods/mod-api.md` engines 示例值同步；`version.json` 随构建重写；
   示例五子棋包 `engines` 维持 `^0.6.0`（更宽也更准的声明，不动）。

## 边界（如实）

- 无抵押/变卖/协商交易：低现金玩家遭遇高租金会猝死（破产是 v1 唯一止损路径）；
- 上限 16 回合的净值裁决是防无限对局的兜底（被动打法约 29 次掷骰；破产局中位
  合计 23 回合）；
- 机会牌序在 `state.deck` 内对双方可读——大富翁信息天然全明，无公平性问题
  （「预知下一张牌」不构成行动优势，因为落点由骰子决定）；
- 视图不自动滚动/高亮滚动到当前格；中央日志只显示最近一手 summary（历史查询
  走 `game_history` 工具）；
- 单骰 1d6、3 级封顶、保释金不实现——均为 v1 裁剪（上表），未来变体应另立
  游戏 id 而非改本引擎；
- 本款在独立 worktree 落地：main 工作树的并行 agent 未受影响，合入由用户决定。
