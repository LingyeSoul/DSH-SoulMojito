## 落法（四层）

1. **引擎**（`builtin/xiangqi.ts`）：9×10 棋盘 32 子、红先；全部常规着法几何规则
   逐一实现（车滑行吃子即止、马八向蹩马腿、象田字塞象眼并不过河、士/将九宫约束、
   炮隔一子吃且炮不能吃炮架、兵/卒过河前只进/过河后可横走/永不后退）；
   将军检测含**将帅照面**（白脸将——同纵线无遮挡视作将/帅对王攻击，走成照面即
   被 `moveLeavesOwnKingSafe` 拒绝，无需特例分支）；终局判定：轮到走子而无任何
   合法着法即终局——被将军为**将死**、未被将军为**困毙**，两种都判负（象棋规则，
   与国际象棋困毙和棋相反，本项目规则面最容易踩错的一条）。形态对齐
   tic-tac-toe/gomoku（TS + 中文报错 + 深拷贝 + 全文无随机/时间源）。
2. **视图**（同文件内联 viewHtml，ASCII 标记 `data-game="dsh-tavern.xiangqi"`）：
   自包含 SVG 棋盘（木色底/双线外框/九宫斜线/楚河汉界/炮兵位角标/纵线号上下
   各九/楷体棋子/最后一手虚实双圈/将军脉冲圈/终局覆盖层/无 token 静态预览局面）；
   **人类回合才启用选子交互**：先点己方棋子选中、再点建议集内高亮目标走子。
   与五子棋视图的差异语义（如实）：五子棋任意空点皆可点（合法性只有「轮到谁」），
   象棋只放行**建议集内目标**——象棋的合法性是局部的（蹩腿/塞眼/炮架/送将），
   放开点击会大量撞 400。
3. **registry**：装载数组加入内置第三款（零其他改动；同 id 遮蔽语义本款无载体——
   没有同 id 的导入参照包）。
4. **gates**：server-bundle 增 `dsh-tavern.xiangqi` 标记（ASCII，引擎 MANIFEST
   与视图 data-game 双处出现）+ 负样本自测（`xiangqi-removed` 全量替换——子串
   救活防护同 gomoku 纪律）。

## 规则面裁剪（v1 明示）

| 面 | 判定 |
|---|---|
| 常规着法几何规则（含蹩马腿/塞象眼/炮架/九宫/过河） | ✅ 全量实现 |
| 将军 / 将帅照面 / 送将禁令（含牵制） | ✅ 全量实现 |
| 将死 / 困毙（双终局判负） | ✅ 实现 |
| 长将 / 长捉 / 循环裁决（重复局面判负判和） | ❌ 不实现（v1 无自动和棋） |
| 自然限着 / 回合数上限和棋 | ❌ 不实现（对局以将死/困毙/认输结束） |

与五子棋「自由规则（无禁手）」同款的分层裁剪纪律：**对局主干完整可玩，循环类
裁决留待需要时单独立项**。边界如实：双方仅循环走子时对局不会自动终局。

## 记谱设计（describe / events / summary 与视图同一套）

- 红方纵线用汉字一-九、黑方用阿拉伯 1-9（均自各自右侧起算：红 file = 9-x、
  黑 file = x+1）；进/退/平三态；车/炮/兵/将进退报步数、马/象/士进退报目标纵线、
  横向一律「平」报目标纵线；同纵线同方同兵种用 前/中/后 消歧（四个以上取
  「前、二、三…、后」——理论可达、实战几乎不可达，取此确定性方案并如实标注）。
- **为什么做完整记谱**：这是 Agent 叙述的自然语言面——「红方 炮二平五」是象棋
  玩家的语言（工具返回的 describe 直接可织入对话）；棋盘行列坐标对不上玩家习惯。
  代价是消歧分支的测试面，已由 games-xiangqi.spec 逐条钉死（含前后/中止三例）。
- events 组装：`[记谱, (吃掉X子), (将军！| 将死/困毙, 本方胜)]`，summary 以
  「，」串联（终局示例：`红方 车九进二，将死，红方胜`）。

## legalActions 语义（与五子棋建议集的差异，如实标注）

- 五子棋：建议集是**启发式子集**（任意空点皆合法，applyAction 全量终审）。
- 象棋：**建议集 = 全部合法着法**（完整性优先）——初始局面 44 步，常规局面
  远低于 §3.2 的 64 上限；吃子优先排序（被吃子力价值降序，其余按起点/终点
  字典序，全确定性）。>64 时按该序截断（理论极端机动局面，本项目实测与文献
  均未见，如实标注为不可达边界）。
- 建议集 ⊆ 终审：games-xiangqi.spec 断言初始 44 步每一条都被 applyAction 原样
  接受（生成器与校验器同一份事实）；applyAction 不读建议集，仍按全量规则终审
  任意动作。

## 视图真机验收（headless Edge，2026-10-14）

四态截图（view 管线渲染 + 自投递 `dsh-tavern:game-state` 下行——与生产同一条
消息路径；`--virtual-time-budget` + 屏内禁用 transition/animation 保截图确定性）：

- 预览（无 token）：静态中炮开局五手局面 + 预览横幅；
- 等待（有 token、首条下行未到）：空盘 + 纵线号/楚河汉界齐备 + 「等待对局状态…」；
- 中局（人类红方回合）：选子高亮（琥珀圈）+ 目标点（空点圆点、被吃子橙圈）+
  最后一手虚实双圈 + 「轮到你走子 · 上一手」横幅；
- 终局（将死）：被将的将/帅红圈 + 覆盖层「红方获胜 · 红方 车九进二，将死，红方胜」。

**截图驱动修两处图像缺陷**（如实留档）：①底排/顶排棋子（半径 23.5 > 原外框
内距 16）压住纵线号并穿出外框——外框移至 ±40、纵线号移至棋子半径外
（上排基线 −27、下排 +36）；②楚河汉界文字与兵/卒纵线（0·2·4·6·8 列）重叠
——横向平移避开。截图与 harness 为一次性验收产物
（`%TEMP%/xiangqi-view-check/`，不入库）。

## 边界（如实）

- 不实现长将/长捉/循环裁决与限着：双方循环走子不会自动终局（出口只有
  将死/困毙/认输）；如需「循环判负」须按新提案加，引擎 state 届时需要历史面。
- 建议集 >64 截断（吃子优先排序）：理论极端局面下列表不完整——视图只放行
  列表内目标、Agent 同受限；实战不可达，留档待证。
- 同纵线同兵种 ≥4 的记谱（前、二、三…后）是确定性自定方案：标准写法在文献中
  不统一（该局面实战几乎不可达）。
- 认输文案：运行时以 `<role> 认输` 合成（red/black 原样），视图做展示本地化
  （「红方认输/黑方认输」）；不改运行时合成文案（跨游戏统一面，避免为单游戏开特例）。
- 终局覆盖层居中可能与穿过中心的最后一手标记/楚河文字视觉重叠（与五子棋
  同款设计；文案完整可读）。
- 0.6.1 宿主不含本内置：需升级插件（桌面档位走自更新；web 档位为源码 link: 时
  重建 dist 后重启 DSH）。
