# DSH 0.2.1-rc.2 深度适配（bind 全 seam 审计 + 工具挂载修复）

日期：2026-10-18。状态：已实施。

需求源：2026-10-18 用户「dsh 更新到 0.2.1.rc2 了，请你深度适配该版本，确认 bind 库每一处是否还能挂载宿主，目前发现工具挂载有问题」。

宿主基准：全局 `@deepseek-ai/dsh@0.2.1-rc.2`（`dsh --version` 实测）；对照版本 `0.2.0-rc.2` 从 npm 取 tarball 逐包 diff。真实宿主挂载用 `runProfile()` 启动 web profile + `ctx.agents.create({ setup: presets.mount })`（脚本见验证段），不是形状断言。

## Problem

0.2.1-rc.2 有四处在不同层面影响本仓库，其中两处直接表现为「工具挂载」：

1. **blank 会话的 preset 身份被宿主复用改回默认（用户报告的 `game_list` 缺失）**。
   会话实证：`~/.dsh/tavern/chats/雪铃/2026-10-18@10h 18m 45s 654ms.jsonl` 对应的
   `session-6c202ab9-…` 日志（v4，54 行）在 `dsh-soulmojito-session` 激活命令后依次写入
   `agent-preset/selected: agent-tavern`、`agent-preset/selected: standard`。Tavern 的
   `sessionBindings` 仍是 `agent-tavern`，但宿主的 `agentPreset` 投影取最后一条，工具面
   停在标准工具（`contextBreakdown.toolsTokens = 7490`，模型 system prompt 是
   「coding agent」；assistant 推理原文「I don't have those tools available… only the
   standard DSH tools」），所以 Agent 回答没有 `game_list`。
   根因：0.2.1 的 `dsh-api-session-controller` 新增 `reuseLive()`——复用 blank 会话时调用
   `presets.select(live, target)`，`target = composition.agentPreset`；客户端
   `uiWorkspace.connectWorkspace(workspaceId)` 不带 preset，于是 `resolve(undefined)` 取宿主
   默认 `standard`。一次并发/重复的 connect 就会在激活命令之后把组合 select 回 standard。
   本仓库的幂等检查用 `some(agent-tavern)`，标记「曾经出现过」就让 recompose 短路，后续
   两条 `dsh-soulmojito-session` 命令（日志 cmd-2/cmd-3）都没有修复。
2. **子代理工具面断裂**。
   `@deepseek-ai/dsh-subagent` 的 `SubagentRuntime.start(provider, request)` 被删除，改为
   `startActivation(spec)`；返回 `childId` 取代 `run.id`，`delivery` 变必填，公开
   `SubagentStartRequest` 删除 `toolFilter`。真机实测 `typeof ctx.subagents.start === 'undefined'`、
   `typeof startActivation === 'function'`。本仓库 `subagentRuntimeOf()` 只认 `start`，因此
   0.2.1 上：
   - `tavern_deduce` 直接报「subagent runtime is unavailable」；
   - `novel_writer_draft` / `novel_writer_delegate` 与小说能力探针同样不可用。
   即工具虽然注册进 preset，执行面却整组失效。
3. **client 宿主 UI 原子表不可解析**。`client-vm-mount` gate 红：`@deepseek-ai/dsh-client-ui-primitives is not resolvable`。0.2.1 不再把该包装进宿主 `node_modules`，模块只存在于 `dsh-web-frontend` 的 `__ModuleLoader__` 内建表；gate 仍按旧路径读包，等于把「宿主换了投递方式」误判成插件失配。
4. **JSONL 持久化包不再导出类**。0.2.0 的 `default` 是 `JsonlSessionPersistence`；0.2.1 只导出 `{ Config, JsonlCompressionSchema, apply, name }`，服务由插件 `apply(ctx, config)` 建立。`repair-v4-sessions` 的宿主 observe 验证因此四个用例全红（`JsonlSessionPersistence is not a constructor`），`verify-tavern-history` 同链路。

结论：bind 库本身没有需要改写的 seam；「工具挂载」的两层问题分别是 **会话 preset 被宿主复用覆盖**（工具注册正确但组合被换掉）与 **子代理 API 换代**（工具在执行面失效），另有 client 原子表投递方式与 JSONL 包导出形状两处工具链适配。

## Decision

### 1. 会话 preset 身份：创建时带 preset + 只认最后一条 selected

- **客户端**：`connectHostWorkspace()` 新增 `options.agentPreset`，三个入口分别传 `agent-tavern` / `agent-novel` / `card-workbench`；0.2.1 的 `uiWorkspace.connectWorkspace(id, options)` 直通 `sessions.create({agentPreset})`，blank 会话从创建起就是目标组合，`reuseLive` 的 target 不再是默认 `standard`。旧宿主忽略第二参。
- **服务端**：`session/preset-marker.ts` 的 `lastSelectedPresetId()` 读最后一条 `agent-preset/selected`；Tavern / Novel / Workbench 三个激活命令从 `some(...)` 改为「最后一条 === 目标」，blank 会话发现被覆盖就 recompose + 补 marker。已开始且最后一条是**另一个显式 preset** 的会话拒绝重选（对齐宿主 `agent-preset/locked` 语义），不再静默写入一个与 live 组合不符的 marker。
- **存量修复**：`repair-v4-sessions.mjs --select-preset <id>` 向已启动 v4 会话追加目标 marker（v4 准入 + 宿主 observe 双验证，备份/回滚）；写回后重启 `dsh web` 或重开会话，resume 路径按最后一条 selected 挂载目标组合。已用用户会话的副本实测：`standard -> agent-tavern`，observe 通过（54 events）。

### 2. 子代理双 API：`spawnSubagent()`

`agent-tavern/deduce.ts` 提供唯一的派生入口，运行时特性检测：

- `startActivation` 存在 → `{ provider, label, request:{prompt,parent,agentPreset?}, signal, delivery:'caller' }`；
  `childId` 映射为 `run.id`，`result`/`dispose` 直接转交。
- 只有 `start` → 旧路径，剥离 `agentPreset`（0.2.0 不认识该字段），保留 `toolFilter`。
- 两者都没有 → 明确抛错（不再静默降级成「可用但永远失败」）。

`delivery: 'caller'` 是刻意选择：推演与写手都是同步消费结果的编排，结果只回工具调用方；`'parent'` 会额外往父会话 inbox 投递一份子代理通知。

### 3. 无工具推理组合：`agent-reasoning` preset

0.2.1 没有 per-spawn `toolFilter`，官方替代是独立 Agent preset。新增：

- `packages/plugin/src/agent-reasoning.ts` → `dsh-soulmojito/reasoning`：`inject:['tools']`，在 preset 挂载域 `tools.restrict({ deny })` 掉全部可见全局工具；宿主启动期全局工具是陆续注册的（真机首轮只看得见 `working_directory`），因此订阅 `tools/change` 并以 250ms 去抖重扫，新增一个 deny 一个，`denied` 记账防重入。
- `cordis.patch.yml` 新增 `preset-agent-reasoning`（`config.id = agent-reasoning`，order 13，只挂 reasoning 模块）。
- `tavern_deduce` 与 `novel_writer_draft`（W1 纯产稿）在 0.2.1 上选择该 preset；0.2.0 仍传 `toolFilter:{allow:[]}`。两条路径都保留，宿主能力决定走哪条。
- 小说能力探针 P2 在 0.2.1 上改用该 preset，从「模型自报 unavailable」升级为宿主强制空工具面（模型仍须报告 unavailable 才算 pass，保持原有判定纪律）。

真机验证：`agent-reasoning` preset 的 agent `tools.schemas(scope)` 返回 `[]`。

### 4. 委托写手（W2）保持父组合

`runDelegatedWriter` 不选独立 preset：写手必须与作者共享同一个 `Symbol.for('dsh-soulmojito:novel-writer-delegations')` 注册表与 novel 工具面（独立 preset 会挂载第二份模块实例）。0.2.1 忽略 `toolFilter` 后，工具层反向闸仍是硬边界：`authorBindingFor()` 对白名单之外的作者工具在委托绑定下必拒。0.2.0 继续由 `toolFilter` 收缩可见面。

### 5. client 原子表改读前端产物

`hostPrimitiveExports()` 先找包（0.2.0 / 未来重新随包安装），找不到时解析 `dsh-web-frontend/dist/assets/index-*.js` 的模块映射与冻结对象键：`"@deepseek-ai/dsh-client-ui-primitives":<id>` + `const <id>=Object.freeze(Object.defineProperty({__proto__:null,` … `},Symbol.toStringTag`。解析出的 288 个名字与 `dsh-client-ui-primitives@0.2.1-rc.2` 包的导出集合逐项一致（实测 288/288），parity 检查继续在浏览器实际加载的那份表上工作。

### 6. JSONL 持久化双形状装载

`scripts/lib/host-session-persistence.mjs`：有 `JsonlSessionPersistence`/`default` 类就直接构造（0.2.0），否则 `await module.apply(context, config)` 后取 `ctx.sessionPersistence`（0.2.1+）。`repair-v4-sessions.mjs` 与 `verify-tavern-history.mjs` 共用，验证工具不跟宿主版本锁死。

### 7. client 产物行尾归一

`client-src` 片段在 Windows 检出上带 CRLF，旧构建原样拼接会生成 2 万行纯行尾 diff。`scripts/build-plugin.mjs` 在拼接后统一 `\r\n → \n`：产物与历史约定一致，生成物 diff 只反映真实语义变化。

## Alternatives considered

- **把 `agentPreset` 加到 `inject` / 依赖宿主版本号分支**：宿主服务面用特性检测已足够，版本号分支会在 rc 之间抖动，否决。
- **推演/写手沿用父组合，只靠 prompt 说「工具不可用」**：0.2.1 上全局 web 工具（duckduckgo_search/vision_understand）仍可执行，纯推理契约变成口头约定；与「fail closed」纪律冲突，否决。代价是推理子代理不再继承父 system prompt——preset 内的子代理仍共享彼此的前缀，跨轮缓存成立。
- **给 W2 也建 writer preset + 只注册白名单工具**：需要把 novel/tavern 工具切片拆成第三份 bundle，且委托注册表虽已 `globalThis` 锚定，工具实现与 store 实例会增加一套；当前工具层反向闸已覆盖越权，判断为过度设计，否决（如未来需要宿主级 allow-list 再立项）。
- **client gate 在找不到原子包时跳过 parity**：会把「宿主改名」重新放回无人防守的盲区，否决；改为读前端产物。
- **repair 脚本锁死 0.2.1 插件形状**：会破坏 0.2.0 用户与旧工件修复，否决。

## Consequences

- 0.2.0-rc.2 行为不变：`start + toolFilter` 路径原样保留；`agent-reasoning` preset 行在 0.2.0 上只是多一个未使用的内部 preset。
- 0.2.1-rc.2 上 `tavern_deduce`/`novel_writer_draft` 恢复可用，且工具面由宿主强制为空；W2 可用，越权由工具层反向闸兜底。
- 新建 Tavern/Novel/Workbench 会话从 `connectWorkspace` 起就带目标 preset；blank 会话即使被宿主再 select 回默认，下一次激活命令按「最后一条 selected」补回。
- **已启动且最后一条 selected 被覆盖的存量会话不会自动热修**：宿主禁止运行中换组合。用 `--select-preset` 补 marker 后重启 `dsh web`/重开会话恢复；本次用户那条 `雪铃` 会话即属此类（副本实测修复成功，原文件未动，因为 `dsh web` 仍在运行）。
- `agent-reasoning` 会出现在 preset 列表（宿主没有 hidden 字段），名称与描述已标注「内部」。
- 推理 preset 的 deny 依赖 `tools/change` 去抖 250ms；宿主若在子代理首轮装配前仍持续注册全局工具，理论上存在极短窗口。当前 web profile 启动完成后不再新增全局工具，实测子代理 scoped schemas 为空。
- 版本连带：根/插件 0.6.6→0.6.7、示例 mod engines、mod-api 示例、README 徽标与测试基线；`version.json` 随构建重建（本地戳不入库）。
- 边界如实标注：`client-vm-mount` 的原子表解析依赖前端 bundle 的压缩形态（`const <id>=Object.freeze(...__proto__:null,...)`）；前端改打包器后 gate 会红并需要更新解析器——这是有意的 fail-loud，不是静默回退。
