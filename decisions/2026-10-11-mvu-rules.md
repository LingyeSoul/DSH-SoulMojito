## 声明形状

变量树根的 `$rules` 子树（数组，与 `$schema` 同链路读取、同剥离纪律——`$rules`
不作为变量结算/渲染/投影）：

```json
"$rules": [
  {
    "name": "favor-unlock",
    "when": "getvar('mvu.favor') >= 80",
    "then": {
      "mvu.flags.trusted": "true",
      "mvu.mood": "\"calm\""
    }
  },
  {
    "name": "debt-relief",
    "when": "vars.mvu.debt > 150",
    "then": { "mvu.debt": "Math.floor(getvar('mvu.debt') * 0.5)" }
  }
]
```

- `name`：1-64 字符，回执归因键（reason 标 `rule:<name>`）；缺名/形状非法 →
  **整卡规则失效** + 警告进回执 failures（不炸结算）。
- `when`：表达式，求值为布尔（truthy 判定）。
- `then`：路径 → 表达式字符串或 JSON 字面量（微调：非字符串值直接作字面量写入，
  手写卡 JSON 里 `"then": {"mvu.flags.trusted": true}` 比 `"true"` 更自然，两者等价）。
- 变量访问以嵌套树语义暴露两个入口：`getvar('<dotted.path>')`（与模板宏同款）与
  `vars`（嵌套对象直访）。
- 上界：单卡 32 条规则（`MVU_RULES_LIMIT`）、单规则 16 个 then 路径
  （`MVU_RULE_THEN_LIMIT`）——与 settle 工具单批 16 项同量级的结算工作界，超限
  按形状非法整卡失效（微调记录：规格未定条数，无界的求值工作与「不炸结算」纪律冲突）。

## 求值沙箱面（确定性强制）

复用 `@dsh-tavern/template` 的 `evalExpressionSandboxed`：node:vm 全新 context、
同步纯构造、无 require/process/timer/网络。在此之上收紧：

| 遮蔽 | 方式 | 效果 |
|---|---|---|
| `Date` | env 置 `undefined` | `Date.now()` / `new Date()` 抛 TypeError → 规则按求值失败跳过 + 警告 |
| `Math` | 冻结白名单视图（abs/ceil/floor/round/min/max/pow/log/三角… 常量 E/PI 等） | `Math.random()` 不存在 → 抛 TypeError；确定性运算可用 |
| `setTimeout` / `setInterval` / `setImmediate` / `queueMicrotask` | env 置 `undefined` | 防御性遮蔽（vm 裸 context 本就无 timer，写明沙箱面） |

**取舍**：规则不进冻结 prompt 上下文，只需结算可复现——沙箱面收紧即可，无需源码
静态筛查。已知边界：vm context 内 `Function` 构造器逃逸可绕过 env 遮蔽访问 vm 原生
`Date`——与 tavern-template 同教义（隔离级别对齐仓库既有 `node:vm` 纪律，不承诺
对抗恶意模板；卡作者是信任方，遮蔽面向「手滑写出不确定性」）。每次求值对工作树
**深拷贝**（剥离控制子树）：表达式里改 `vars` 引用不落树、绕不过守卫。

## 执行语义

- **挂接点**：守卫 pass 之后、回执 diff 之前——规则在守卫后的树上做二次计算。
- **规则产出再过一次守卫**（对齐 C-1 既有语义）：clamp/step 调整值写回进正常
  回执，reason = `rule:<name>; <guard note>`；reject（type-mismatch /
  enum-violation / readonly / structure）→ 失败项 `${path}: rule '<name>': guard
  <kind>: <reason>`（可重试）。规则写入 `$schema`/`$rules` 子树恒拒（契约不可经
  规则写入）。
- **链式求值 + 有界不动点**：规则按声明序对工作副本求值，前一规则的效果对后续
  规则可见；一轮内产生了**实际变更**（守卫后值 ≠ 写前值）则再跑一轮，最多 3 轮
  （`MVU_RULE_ROUNDS`）。不动点判据取「实际变更」而非「when 命中」：阈值置位类
  规则第二轮同值幂等天然收敛，不会假触发上限；到上限仍在变更 → 警告进回执
  failures 如实记录（卡作者需收窄 when 或调整声明序）。多轮/多规则触发同一路径
  的回执 reason 按序去重拼接（`rule:A; rule:B`；同段不重复）。
- **失败纪律与 templateWarnings 同款**：`when`/`then` 求值抛错 → 该规则**本轮
  原子跳过**（then 值先全部求值再写入，任一失败不部分落盘）+ 警告进 failures；
  `then` 求值结果为 `undefined` 拒写（不触发删除语义，删除不在 v1 规则能力内）。
- **回执**：规则变更与模板写穿变更合入同一张回执（`MvuVariableChange.reason`
  复用 C-1 的可选字段）；模板与规则同轮写同一路径时，守卫 note 与规则 note 以
  `; ` 合并（guard 先、rule 后——时间序如实）。
- **无 `$rules` 恒等**：行为与 C-2 之前逐字节一致（golden 锁死）。

## 两个消费面（C-1 同款：共享纯函数核 + 薄挂接）

1. **ST 生成 + `POST mvu/retry`**（mvu-rules.ts `applyMvuSettlementRules`）：
   `applyMvuSettlementGuard` 之后、`recordMvuTurnReceipt`/diff 之前对
   `chat_metadata.variables` 整树跑规则；生成路径规则告警使回执 status='failed'，
   retry 路径维持「retry 不产生 failed 状态、告警只进 failures」既有约定。
2. **AgentTavern `tavern_variable_settle`**（agent.ts 工具内规则相）：逐项 flat 写
   完成后，在「flat 写后的树快照」（写前 flat 全量 `list` + 聊天播种树 overlay +
   本轮成功写入 overlay）上跑同一 `runMvuRules`；规则写入逐条 get→set CAS 落
   chat 作用域 VariableStore（同路径多轮触发只持久化终值），回执 change 与审计线
   都带 `rule:<name>`；before 取覆盖视角的写前树值。

`$rules` 契约自改回滚（微调记录：规格未明说，对齐 C-1「守卫不可自改」纪律）：
模板写穿改了根 `$rules` 本身 → 回滚到基线值 + readonly 失败项。放在规则模块
而非守卫 pass，因守卫 pass 在无 `$schema` 的卡上恒等早退，而 `$rules` 可独立于
`$schema` 存在。

## 剥离矩阵（`$rules` 与 `$schema` 同纪律）

| 消费面 | 处理 |
|---|---|
| 回执 diff（结算投影） | `diffVariables` 两侧剥离（stripMvuControl，下同） |
| 状态栏渲染 | `renderMvuStatusTemplate` 的 local/initial 绑定剥离 |
| `GET mvu/status` 载荷 | `displayVariables` 剥离（含 AgentTavern overlay 分支）；`POST mvu/retry` 响应的 `variables` 同 |
| chat 作用域 VariableStore | 无需剥离——store 名字校验本就不含 `$` |
| 模板运行时 getvar | 不剥离（绑活树写穿语义不能换成拷贝；与 `$schema` 同判） |
| 规则求值 env | 剥离（控制契约不是变量，表达式不可读 `$rules` 自改触发） |

## 撤销交互（B-6a）

规则产生的变更与模板写穿变更同回执同字段——撤销恢复 before 值即可，规则路径的
新增键同样删除。**撤销后若条件仍满足，下次结算规则重触发**：撤销恢复的是值，不
是「规则不再跑」；这是语义正确行为（状态回去了，由该状态派生的结论也回去重算）。
注意 schema 模板锁定的字段不可经撤销删除（B-6a 既有守卫筛选，规则写入的路径若被
声明为模板字段，撤销删除会被拒——卡作者用开放对象 `{}` 承接规则派生键）。

## 与 LWB varevent 的差异（及理由）

| # | varevent | 本实现 | 理由 |
|---|---|---|---|
| 1 | 中文操作词别名（`当…则…`/`增加`/`设为`）+ 自然语言规则体 | **不做别名**：`when`/`then` 是 JS 表达式 | dsh 的写入走模板写穿不是自然语言解析；表达式复用模板沙箱零新语法面，卡作者本就在写 EJS 模板 |
| 2 | 回合后排队执行（after-ai-gate DOM 稳定检测 + ticket 队列） | 结算相位内联执行（服务端 post-save 单点） | D-3 评估结论：dsh 无浏览器 DOM 竞态，排队基础设施无对应暴露面 |
| 3 | 规则可写自然语言描述的复合动作 | then 只有路径写（无删除/无循环/无跨回合状态） | v1 从严：确定性可复现的最小面；删除与复合动作等真实需求出现再立项 |
| 4 | 事件订阅模型（变量变化触发监听器） | 声明序遍历 + 有界不动点 | 规则即数据不是代码；声明序可预测，3 轮上限防互触发死循环 |
