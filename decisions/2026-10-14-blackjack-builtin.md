## 形态裁定（v2 最终面）：玩家 vs AI 庄家

需求源「改成AI做庄」（2026-10-14 用户在 v1 落地前的中途改版）。v1 曾按
sessions.ts 的 v1 硬裁剪（会话恒为「一人类一 Agent」双人对局）把 21点落成
「双方各执一手牌对赌、庄家只是引擎机制」；用户裁定改为**真正的庄家角色**：

- roles `['player', 'dealer']`——人类缺省执 `player`、Agent 缺省执 `dealer`
  （sessions.start 的 humanRole 缺省 roles[0]、game_start 的 role 缺省取另一方
  →「AI 做庄」是开箱默认）；
- **庄家手由 Agent 真实来打**：庄家回合轮到 Agent，它逐张补牌、最后停牌——赌场
  家规由引擎强制执行（<17 点只许补牌、≥17 点只许停牌；引擎即监察，违规动作中文
  抛错）——规则公平性不打折，但每张补牌都是 Agent 的一手决策调用 + 叙述素材；
- 玩家爆牌即结算（赌场同规：无人可比则庄家不补牌）；玩家停牌时**亮暗牌**（同一
  手 applyAction 内揭晓），庄家随后按家规补牌至 ≥17 停；
- 裁决：玩家爆→庄家胜；庄家爆→玩家胜；比点数高者胜；同点平局（winner=null）。
- 与军棋/象棋的「对称双人」形态不同：本款是非对称角色（玩家 vs 庄家）+ 家规
  强制的引擎语义——RolesJustified：非对称双人恰是 21点的本义。

v1 留档（为什么曾那么做）：v1 约束下「一人类一 Agent」的对称双人对赌是对 21点
的妥协形态——但它把「庄家」物化成无关的叙事道具，胜负只在两人之间比较，与
玩家对 21点的直觉（我 vs 庄家）不符；用户中途裁定即修此。v1 引擎/spec/视图
（hands.first/second、both-vs-house 比较）整体重写为 v2。

## 暗牌公平性设计（两版共通的最关键一条）

桥契约里 state 对视图（game-state 下行）与 Agent（game_state 工具）**全明**，
没有按角色脱敏的面——若庄家暗牌在发牌期就进 state，任何一方翻 devtools 或调
game_state 即可偷看。落法：**暗牌延迟决定**——

- 玩家回合期间庄家只有 1 张明牌（视图画一张纯装饰牌背，不承载任何点数信息）；
- 暗牌在**玩家停牌那一刻**（stand 的 applyAction 内）才从牌靴游标续发并立即
  亮明（`庄家亮出暗牌：♠K（合计 21 点）`）——「信息不存在」是全明 state 下唯一
  防偷看手段，且此时玩家已无决策可受影响；玩家爆牌的结算同样补发并亮明（不补
  更多牌，赌场同规）；
- 统计等价性（如实）：对玩家而言，「洗好的靴里某张未知牌」与「停牌时才决定的
  随机流」同为均匀未知分布——赌场式「先扣暗牌」的拟真序在本桥形态下没有信息
  价值，只输掉公平性；
- 牌靴 = 分块确定性流：第 k 块用 mulberry32(seed ⊕ k 混淆) 对 0..51 做
  Fisher-Yates，取之不尽（无重洗/耗尽边界 case）；seed 缺省取 node:crypto
  随机整数（全文除该处外禁 Math.random/Date.now，spec 扫源码钉死）。

## 规则面裁剪（v1 明示）

| 面 | 判定 |
|---|---|
| 要牌/停牌、A 软硬点数（1/11 取不爆最大）、J/Q/K=10 | ✅ 全量实现 |
| 玩家：到 21 自动停牌（含初始天牌）、爆牌即结算 | ✅ 实现 |
| 庄家：家规强制（<17 只补、≥17 只停，S17 软 17 也停）、爆牌即结算；亮暗牌 | ✅ 实现 |
| 裁决：爆牌负、比点高者胜、同点平局（无天牌 3:2 赔付——无筹码面） | ✅ 按点数比较 |
| 下注 / 加倍 / 分牌 / 保险 / surrender | ❌ 不实现（v1 无筹码语义，动作面只有 hit/stand） |
| 天牌（blackjack natural）特殊结算 | ❌ 不实现（两张 21 只是点数 21 的手；自动停牌覆盖） |
| 数牌 / 牌靴张数披露 | ❌ 不实现（state 只带游标 dealt，不披露剩余牌序） |

与五子棋「自由规则」/象棋「无循环裁决」同款分层纪律：对局主干完整可玩，
赌场周边面留待需要时单独立项。**家规强制是 v2 的公平性基石**：若庄家可自由
决策（例如 12 点即停），庄家优势远超真实规则，对局失衡——故引擎把家规做成
非法动作闸，Agent 的庄家操作面 = 家规允许的唯一动作。

## 叙述面（describe/events/summary 与视图同一套）

- 牌面文本 `花色+点数`（♠A / ♥10 / ♦K / ♣Q）；角色 = 玩家 / 庄家（庄家动作
  词汇是「补牌」不是「要牌」）。
- events 形态：`玩家要牌得 ♥8（当前 16 点）`、`玩家停牌（18 点）`、
  `玩家已到 21 点，自动停牌`、`玩家爆牌（23 点）`、`庄家亮出暗牌：♠K（合计 21 点）`、
  `庄家补牌得 ♦4（当前 20 点）`、`庄家停牌（19 点）`、`庄家爆牌（23 点）`；结算收尾
  `结算：玩家 18 点、庄家 19 点——庄家胜`（`——玩家胜`/`——平局`）、单爆
  `结算：玩家爆牌（23 点）——庄家胜`；summary 以「，」串联。
- describe 在落子前 state 上取（Agent 织入对话的自然语言面，与象棋记谱同一设计
  动机）：玩家 `玩家要牌（当前 14 点）`/`玩家停牌（当前 14 点）`；庄家
  `庄家补牌（当前 12 点）`/`庄家停牌（当前 19 点）`。

## 落法

1. **引擎**（`builtin/blackjack.ts`）：state
   `{ turn:'player'|'dealer', seed, dealt, hands:{player,dealer}, totals:{player,dealer}, finished, winner }`
   （Card = `{r,s}`；totals 为引擎维护的最佳点数；玩家回合期 dealer 为明牌点数）——
   无需 stood 旗（玩家定局 = turn 变 dealer）。开局玩家 2 张 + 庄家 1 明牌；
   玩家初始 21 自动停牌 turn='dealer'。玩家回合 legalActions 恒 `[hit,stand]`；
   庄家回合按家规恰 `[{hit}]`（<17）或 `[{stand}]`（≥17）。校验序镜像 gomoku
   （形状 → type → 未终局 → 角色 → 回合 → 家规），深拷贝不改入参，中文报错。
   终局不变量：finished ⇒ hands.dealer.length ≥ 2（暗牌必已亮）。
2. **视图**（同文件内联 viewHtml，`data-game="dsh-tavern.blackjack"`）：绿绒
   赌桌配色；上方庄家区（玩家回合明牌 + 装饰牌背；亮牌后只显牌），下方玩家区
   （ownerOf 标注「你」/「AI」，点数爆牌红示、21 点金示）；玩家回合才启用
   「要牌」「停牌」按钮；banner 四态（turn-player/turn-dealer/finished/preview）；
   **终局结果条（2026-10-14 截图驱动两级修订，如实留档）**：初版沿棋盘类
   覆盖层（rgba .74）——真机读数白卡渗色可辨（终局文字与手牌标签糊在一起）；
   一级修订压到 .92 仍有残影，且「覆盖层遮住盘面」与 0.6.3 既定语义「游戏
   结束时应该显示游戏盘面」冲突；二级修订**废弃覆盖层，改 in-flow 结果条**
   （`.result-strip` 盘面之下的金描边面板：`#101812` 底 +
   `rgba(202, 168, 79, .5)` 描边，大字 `玩家胜`/`庄家胜`/`平局` + 结算全句
   限宽换行）——终局盘面完整保留（这正是对局的 payoff：看庄家摊开的手牌）、
   文字零叠压、文字对比度不受底色影响。无 token 静态预览局面。
3. **registry / gates**：装载数组第五款；server-bundle 增
   `dsh-tavern.blackjack` 标记 + `blackjack-removed` 负样本自测（与军棋 lane
   同款并存）。
4. **并行施工方式（本款特有，如实留档）**：引擎+视图（Agent A）与测试
   （Agent B，蓝军角色——独立于实现按同份契约施工，断言只锁不变式与契约面，
   不镜像洗牌实现）两会话并行；集成/验证/文档由主线合并。v1 与 v2 各跑一轮
   （v2 为「改成AI做庄」改版重做）。

## 边界（如实）

- 庄家是 Agent 角色但动作面被家规钳到唯一（<17 补、≥17 停）：这是**规则公平性
  的刻意设计**，不是实现偷懒——庄家自由决策会显著抬升庄家优势；如未来要
  「庄家可自由决策」的娱乐变体，应另立游戏 id 而非改本引擎。
- totals 是引擎维护的冗余派生面（可由 hands 重算）：以引擎产出的值为权威，
  spec 用独立点数函数对账而非镜像引擎实现。
- 玩家爆牌结算时庄家不补牌只亮牌（赌场同规）；庄家爆牌对「玩家已爆」不可达
  （玩家爆即结算）。
- 平局/同点、庄家爆牌胜负的 winner 语义：'player'/'dealer'/null，与框架
  角色字符串一致；resign 由运行时统一处理（引擎收到抛错）。
- 0.6.3 宿主不含本内置：需升级插件（桌面档位走自更新）。
