# 正则脚本按来源分区与整段删除

> 日期：2026-10-23。承接 `2026-10-22-card-scoped-regex-and-worlds.md` 与 `2026-10-23-scoped-regex-identity-and-world-toggle.md`（同名实体拆分）。用户需求：正则列表按角色卡或预设分区，并提供按分区删除。

## 问题

正则归属已经按来源记录（`regexScriptOwners` / `regexScriptPresetOwners`），但面板仍是一条平铺清单：每行只带一个小号来源徽标。一次「从角色卡同步」可能带进几十条脚本、同名的跨卡实体又各自成行，用户无法快速判断「哪些是这张卡的」「这个预设到底塞了多少条」，清理某个来源只能逐行找、逐行删。

## 决策

- **分区是派生视图，不新增持久态**。分组键由既有归属表计算：卡归属优先 → 预设归属 → 无归属为全局。渲染顺序固定为全局、角色卡、预设，组内按来源名排序；当前激活的卡/预设所在组带「当前」徽标。
- **段头数字与删除范围始终是该来源的全部脚本**。过滤框只收窄组内可见行；即使过滤隐藏了部分脚本，段头仍显示总条数，「清空分区」也按总数删除，避免留下看不见的残留。
- **整段删除复用既有全量替换契约**。前端把该组之外的所有脚本交给 `PUT /regex`（`replaceRegexScripts`），服务端在写盘时同步剪掉被删 id 的两张归属表；没有新增路由、迁移或第二套来源记录。
- **删除要确认，且不打断编辑**。确认文案带来源名与条数；编辑器打开时分区删除按钮禁用；删除后若正在编辑的脚本属于该组，编辑态一并关闭并给回执。

## 边界

- 旧数据里同一 id 同时登记在卡与预设两张归属表时，分区按卡归属展示（与行内双徽标并存），清空该卡分区会删除这一条实体——归属表仍指向同一实体，不做半删除。
- 分区不提供折叠或重命名：脚本规模靠过滤框收窄，来源名本身来自角色卡/预设资产，改名应走原资产管理面。
- 分区视图只在管理面板的正则分区生效；生成期 `collectRegexScripts` 的合并/生效语义不变。
