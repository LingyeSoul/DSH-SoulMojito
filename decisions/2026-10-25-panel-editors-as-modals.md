# 管理面板编辑器改为弹窗

> 日期：2026-10-25。用户需求：管理面板里原本内联展开的编辑器改为弹出对话框编辑；用户人设的新建与编辑也不再用浏览器 `prompt`。

## 问题

角色卡、世界书、预设与正则脚本的编辑器原先嵌在清单行或卡片网格中展开。大表单会把清单推走，编辑期间列表与草稿混在同一滚动面；正则条目还会把编辑器塞进分区折叠层，导致定位和取消都不直观。用户人设的新建只弹名称 `prompt`、编辑只弹描述 `prompt`，既无法一次看清字段，也绕过了面板现有的未保存确认。

## 决策

- **统一弹窗壳 `EditorDialog`**：基于宿主 `Modal`（`headless`），提供标题、关闭按钮、可滚动正文与独立 footer；宽度 900px、高度 780px，窄屏回落视口减 24px。
- **编辑器动作移出滚动正文**：`dt-editor-toolbar` 作为 `EditorDialog` 的 `footer` 固定在正文外，取消/保存始终可见，滚动时不再盖住字段。
- **五类编辑器全部走弹窗**：`CardEditor`、`WorldBookEditor`、`PresetEditor`、`RegexScriptEditor` 与 `PersonaEditor` 各自在组件内包一层 `EditorDialog`，父级只负责挂载/卸载，不再在清单里渲染表单。
- **用户人设表单化**：新建弹窗同时填写名称与描述；编辑弹窗名称只读、描述可改。名称、空值和重名在客户端先拦，错误显示在弹窗内。
- **草稿守卫不丢**：`EditorDialog` 的 `onClose` 接各编辑器的 `cancel`，遮罩点击与 Escape 同样经过未保存确认；`CardEditor` 的浏览器级 `beforeunload` 保护保持不变。
- **列表回执保持原语义**：保存后仍刷新缓存、展开目标正则分组或停留在浏览态；新建成功后仍进入新资产的编辑/浏览态。
- **加载态也在弹窗内**：角色卡与世界书在数据未到达时先显示弹窗 + loading；预设缺数据时用同壳 loading，避免无反馈。

## 边界

- 不改变任何读写路由、落库格式、资产缓存键或服务端校验。
- 用户人设名称创建后不可改：现有 `PUT persona` 只更新描述与位置字段，没有改名契约；改名需要同步头像与 `activePersona` 引用，留作独立需求。
- 不改变正则分区折叠、归属切换与批量操作语义；编辑中的分区仍按既有逻辑强制展开。
- 不把 `PanelScripts` 的粘贴导入框、变量行内输入、持续指引单行输入当作资产编辑器改造。
- 弹窗仍是纯视图状态，不持久化打开位置或滚动位置。

## 验证

- 新增 `packages/plugin/tests/panel-editor-modals.spec.ts`：锁定弹窗壳、footer 位置、五类编辑器的挂载点、旧内联/`prompt` 挂载点移除与 zh/en 标题键。
- `pnpm run check`：tsc + 全部测试 + 构建 `client/main.js`/`client/index.js` + 18 项 gates（含 locale 键与源码行数预算）。
