## 落法（四层）

1. **引擎**（`builtin/junqi.ts`）：5×12 棋盘、每方 25 子（司令/军长/师长×2/
   旅长×2/团长×2/营长×2/连长×3/排长×3/工兵×3/地雷×3/炸弹×2/军旗）、红先。
   棋盘几何以**边集合**单源实现（RAIL_EDGES/ROAD_EDGES → 邻接表）：铁路 =
   横线 y∈{1,5,6,10} 全列 + 纵线 x∈{0,4} 贯通 y=1..10（跨前线）+ 中线
   (2,5)-(2,6) 过桥；公路 = 纵线全域（含底线向前）+ 内排横线（底线无横线）
   + 行营斜线八达 + 大本营斜线三向；前线（y=5↔6）只有 x∈{0,2,4} 三处铁路
   过桥。公路边集合刻意排除铁路边（同一条边不进两个集合）——「铁路上走一步」
   由铁路规则覆盖，单一事实来源。
   走法生成：公路一步（任何可动子）；非工兵铁路**直线**滑行任意距离（固定
   方向不可拐弯、遇子即止不可穿越）；工兵铁路 BFS 任意路径（可转弯、不可
   穿越占子）；地雷/军旗永不可动；**进入大本营的棋子（含初始就位）不能再
   动**；行营宿子免攻（进营只可落空营）。战斗裁决单一收口（resolveCombat）：
   大吃小占位、小攻大阵亡、同级同尽、炸弹对任何子（含地雷）同尽、地雷克
   一切非工兵、工兵挖雷、**扛走军旗即胜（任何攻击子含炸弹）**。终局两途：
   夺旗与困毙（对方轮到走子而无任何合法着法判负——军棋无子和棋）。形态
   对齐 family（TS + 中文报错 + 深拷贝 + 全文无随机/时间源）。
2. **视图**（同文件内联 viewHtml，ASCII 标记 `data-game="dsh-tavern.junqi"`）：
   自包含 SVG 棋盘（木色底/铁路双线渲染：深色粗轨+浅色枕木虚线/公路细线/
   行营虚线圆（空营标「行营」）/大本营着色圆角底（空营标「大本营」）/前线
   带与「前线」小字/行列坐标/红蓝矩形棋子（军棋棋子形制）/最后一手虚实
   双椭圆/终局覆盖层/无 token 静态预览局面）；**人类回合才启用选子交互**：
   先点己方棋子选中、再点建议集内高亮目标走子。与象棋视图同款语义：只放行
   建议集内目标——军棋的合法性是几何的（铁路拐弯/行营免攻/穿越占子），
   放开点击会大量撞 400。
3. **registry**：装载数组加入内置第四款（零其他改动；同 id 遮蔽语义本款无
   载体——没有同 id 的导入参照包）。
4. **gates**：server-bundle 增 `dsh-tavern.junqi` 标记（ASCII，引擎 MANIFEST
   与视图 data-game 双处出现）+ 负样本自测（`junqi-removed` 全量替换——子串
   救活防护同 gomoku/xiangqi 纪律）。

## 规则面裁剪（v1 明示）

| 面 | 判定 |
|---|---|
| 常规着法几何（公路/铁路直线/工兵铁路转弯/行营八向/大本营三向/冻结） | ✅ 全量实现 |
| 战斗裁决（大小/同级/炸弹/地雷/工兵挖雷/扛旗） | ✅ 全量实现 |
| 行营免攻、大本营可攻（扛旗通道） | ✅ 实现 |
| 终局：夺旗 / 困毙判负 / 认输（运行时） | ✅ 实现 |
| **暗棋（子力隐藏）** | ❌ 不实现——**接口事实裁定**：桥 v1 的视图载荷（sessions.viewOf）与 game_state 工具都是全量 state 下发，无按角色投影的通道；暗棋会把双方子力同时泄露给浏览器与 Agent（双向作弊面）。明棋是契约下的诚实变体，不是规则偏好。 |
| **布阵阶段（自由摆子）** | ❌ 不实现——运行时 sessions.start 调 createGame() **不传参**（无 seed 通道），随机布阵无从谈起；自由布阵需要「双方各摆 25 子」的交互面（工具+视图+校验三层），远超内置款的开箱可玩面。取**经典固定布阵**（镜像对称），对局确定性可复现。 |
| 翻棋变体 / 四国军棋 | ❌ 不实现（同款分层裁剪纪律——需要隐藏信息通道与四方会话，均非桥 v1 面） |
| 长捉循环裁决 | ❌ 不实现（与象棋 v1 同款——对局主干完整可玩，循环类裁决留待单独立项） |

边界如实：双方仅循环走子时对局不会自动终局（出口只有夺旗/困毙/认输）。

## 固定布阵设计（决策记录）

红方（y=6..11，蓝方 y 镜像同子小写）：

```
后排  y=11： 团长  军旗HQ  地雷  旅长HQ  地雷
二排  y=10： 排长  地雷    司令  军长    师长
三排  y=9：  工兵  [营]    炸弹  [营]    工兵
四排  y=8：  连长  师长    [营]  旅长    炸弹
五排  y=7：  排长  [营]    营长  [营]    排长
前排  y=6：  工兵  连长    营长  团长    连长
```

- 约束全满足：军旗在大本营 (1,11)、地雷 3 枚全在后两排、炸弹 2 枚不在前排、
  行营全空、25 子恰好填满 25 个非行营位（军棋布阵的满员特性）。
- 设计取舍：司令居 (2,10) 二排中枢（铁路交叉口、机动强）；两枚炸弹分守
  中路 (2,9) 与右翼 (4,8)；军旗左大本营、地雷护旗（右 (2,11) 与正前
  (1,10)）；右大本营放旅长作「假旗位」诱饵（大本营宿子冻结，损失有限）。
- 布阵写死在 RED_LAYOUT 常量（25 元组数组），蓝方由镜像生成——单一事实
  来源，测试逐格钉死 + 子力计数对账（M1/G1/D2/B2/R2/T2/C3/P3/E3/Z2/L3/F1
  每方）。

## 记谱设计（describe / events / summary 与视图同一套）

- 军棋无通行棋谱记法（不像象棋有「炮二平五」），取**坐标叙述**：
  `红方 营长 (2,7)→(2,8)`；非公路边的连接（即铁路机动）加「沿铁路」后缀；
  战斗结果随事件（吃掉蓝方军长 / 与蓝方营长同归于尽 / 触雷阵亡（地雷仍在）/
  进攻阵亡（蓝方司令仍在）/ 挖掉蓝方地雷 / 扛走蓝方军旗！）。
- **为什么不做发明式记谱**：describe 是 Agent 叙述的自然语言面，坐标即
  动作面（from/to 与 move 动作同构）——发明一套玩家对不上的假记谱只会
  增加双射成本。坐标+子力名+结果三元组已无歧义。
- events 组装：`[叙述, (战斗结果), (夺旗获胜|对方无棋可走, 本方胜)]`，
  summary 以「，」串联（终局示例：`红方 工兵 (0,1)→(1,0)，扛走蓝方军旗！，
  夺旗获胜，红方胜`）。

## legalActions 语义（与五子棋建议集的差异，如实标注）

- **建议集 = 全部合法着法**（完整性优先，与象棋同款）：固定布阵初始局面
  **34 步**（含三条铁路相邻攻击与五步行营斜线机动——手算曾得 29，漏了
  第 10 排子力经行营斜线进 (1,9)/(3,9) 营的 5 步；隔离验证 harness 对账
  后钉死 34，见「测试对账」节）；常规局面远低于 §3.2 的 64 上限。
- 排序确定性：吃子优先（被吃子威胁价值降序：军旗>司令>军长>师长>旅长>
  炸弹>团长>营长>连长>排长>地雷>工兵），其余按（起点 y,x → 终点 y,x）
  字典序。>64 时按该序截断（理论极端机动局面）。
- 建议集 ⊆ 终审：games-junqi.spec 断言初始 34 步每一条都被 applyAction
  原样接受（生成器与校验器同一份事实）；applyAction 不读建议集，仍按
  全量规则终审任意动作。

## 视图真机验收（headless Edge，2026-10-14）

与象棋同款 harness：view 管线渲染（renderGameViewDocument）+ 自投递
`dsh-tavern:game-state` 下行（与生产同一条消息路径）+ `--virtual-time-budget`
截图。四态验收：

- 预览（无 token）：静态四手局面 + 预览横幅，铁路双线/行营虚线圆/大本营
  着色底/前线带/行列坐标/最后一手虚实双椭圆齐备；
- 等待（有 token、首条下行未到）：空盘 + 空营「行营」/空大本营「大本营」
  标字；
- 中局（人类红方回合 + 模拟点击选中营长 (2,8)）：琥珀选中圈 + 恰好四个
  建议集目标点（(1,7)/(2,7)/(1,9)/(3,9)）+ 横幅「红方 · 轮到你走子 ·
  蓝方 团长 (3,5)→(3,4)」；
- 终局（夺旗）：覆盖层「红方获胜」+ 完整 summary（扛旗叙述串）、棋盘暗化
  保留盘面（用户 2026-10-14 需求「游戏结束时应该显示游戏盘面」的军棋面）。

**截图驱动修一处图像缺陷**（如实留档）：行营/大本营文字被穿格而过的斜线、
公路从字面压过（1.9× 放大截图实况）——修法：空营/空大本营的文字加与格底
同色衬底（圆 r=11.5 / 矩形 44×14，色取底色叠加后的实色 #dcc597 / #d0ba8d），
线段被衬底压住、文字可读；修复后全盘放大复验通过。另核实：行列坐标 1-12/1-5
渲染完整（DOM dump 对数：11 号行标存在）、行营 10 处/大本营 4 处标字在 SVG 实渲。
截图与 harness 为一次性验收产物（`%TEMP%/junqi-view-check/`，不入库）。

## 边界（如实）

- 明棋变体：双方子力全程互相可见（接口事实裁定，见规则面裁剪表）；如需
  暗棋须先给桥加按角色投影的视图/工具通道（新提案面）。
- 固定布阵：每局同型开局（对称镜像）；布阵阶段与随机布阵需 createGame 的
  options 通道（运行时现在不传参）或新交互面，均留待需要时立项。
- 建议集 >64 截断（吃子优先排序）：理论极端局面下列表不完整——视图只放行
  列表内目标、Agent 同受限；固定布阵常规对局远不可达，留档待证。
- 认输文案：运行时以 `<role> 认输` 合成（red/blue 原样），视图做展示本地化
  （「红方认输/蓝方认输」）；不改运行时合成文案（跨游戏统一面）。
- 循环走子不自动终局（长捉裁决裁剪，与象棋 v1 同款）。
- 0.6.3 宿主不含本内置：需升级插件（桌面档位走自更新；web 档位为源码 link:
  时重建 dist 后重启 DSH）。
