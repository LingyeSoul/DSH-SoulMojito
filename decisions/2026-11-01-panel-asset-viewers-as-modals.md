# 管理面板资产查看改为弹窗

> 日期：2026-11-01。用户需求：世界书、角色卡、预设的「查看」也要像「编辑」一样弹出对话框查看。

## 问题

角色卡、世界书与预设的编辑器已经统一为独立弹窗，但「查看」路径仍留在清单里：

- 角色卡的「查看卡面」在卡片网格内展开字段手风琴，展开后会把同排其他卡片向下推走；
- 世界书的「N 条目」在清单下方展开浏览分区，搜索框与条目列表插在两段清单之间，滚动位置和编辑入口分离；
- 预设此前只有「编辑」，没有只读查看入口。

查看是把清单行当作原地容器，编辑是弹窗，两条路径的交互形态不一致。

## 决策

- **查看走同一弹窗壳**：新增 `CharacterCardView`、`WorldBookView`、`PresetView`，全部基于 `EditorDialog` 渲染，追加 `dt-asset-modal` 修饰类（760px 宽、高度随内容、超出视口滚动）。
- **只读与编辑分离**：查看弹窗只渲染内容，不挂任何 `input`/`textarea`/`toggle`；底部固定左「关闭」、右「编辑」，编辑按钮把已加载的资产直接交给对应编辑器，不再重新拉取。
- **清单行不再原地展开**：角色卡移除内联 `CharacterCardFields`；世界书移除清单下方的浏览分区，条目搜索移入查看弹窗；预设行新增「查看」按钮，与「编辑」并列。
- **数据懒加载保持不变**：查看与编辑共用 `cards` / `books` / `presets` 缓存和 `fetchCharacterCard` / `fetchWorldBook` / `fetchPreset`；未加载时弹窗内显示 loading，失败时关闭弹窗并在分区底部显示原有错误。
- **保存回执保持原语义**：角色卡/世界书保存后打开对应查看弹窗，创建成功后同样进入查看弹窗；预设保持保存后回到清单。
- **新分片承载查看器**：`90b-panel-views.js` 单独存放三个只读组件与 `loreKeys`，避免 `90-panels-core.js` 超出 800 行源码预算。

## 边界

- 不改变任何读写路由、落库格式、资产缓存键或服务端校验。
- 查看弹窗是纯视图状态，不持久化打开位置或滚动位置。
- 世界书查看弹窗的搜索只过滤当前已加载条目，不改变生成侧的世界书激活逻辑。
- 角色卡的 `extensions`、`characterBook` 等高级字段不在只读视图展开，仍通过「编辑」中的高级 JSON 字段查看。

## 验证

- 新增 `packages/plugin/tests/panel-asset-views.spec.ts`：锁定三个查看器均包在 `EditorDialog` + `dt-asset-modal` 中、清单行挂载点、旧内联查看路径移除、预设查看按钮与 zh/en 文案键。
- 既有 `packages/plugin/tests/panel-editor-modals.spec.ts` 的五类编辑器弹窗断言保持通过。
- `pnpm run check`：tsc + 全部测试 + 构建 `client/main.js` / `client/index.js` + gates（含 locale 键与源码行数预算）。本实现实测通过：197 个测试文件 / 3268 passed / 2 skipped，20 项 gate 全 PASS。
- 真实浏览器验收：桌面 1440×900 与手机 390×844 两种视口下，角色卡、世界书、预设的查看弹窗与「查看 → 编辑」交接均走通；世界书长条目只随弹窗正文滚动，无嵌套滚动条。
